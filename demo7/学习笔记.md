- <code>给 greet_user 增加空名字处理</code>：当前 project_workspace/utils.py 已经包含空名字判断，空字符串会返回 “Hello, friend! It's nice to meet you!”。因此这个练习在当前代码中已经完成。复盘正确链路应是先用 search_text 定位 greet_user，再用 read_text_file 确认实现；发现需求已满足后应停止修改并报告，不应该为了“完成任务”重复改代码。

## 总结

demo7 在 demo6 框架上实现最小 Coding Agent，核心行为是先观察、再定位、再读取、最后精确修改。coding_tools 将工具分成观察型与修改型，用工作区沙箱限制访问范围，并通过 expected_occurrences 防止误替换。真正成熟的 Coding Agent 还需要 diff、语法检查、测试、版本控制和回滚。

## Runtime 继承与方法重写练习

完成日期：2026-10-12。lesson_08_runtime_inheritance.py 通过 3/3 项检查。

CodingAgentRuntime 继承 AgentRuntime，复用主循环，并重写 create_state 定制代码任务状态。先用 super().create_state(goal) 获取通用状态，再向 shared_context 添加 workspace_dir，最后返回状态。

练习通过 state["shared_context"]["workspace_dir"] = "project_workspace" 添加字段，不替换整个 shared_context，因此可以保留父类今后加入的其他上下文字段。原项目当前父类返回空 shared_context，直接赋一个新字典也能得到相同结果。

父类方法中的 self 仍指向实际子类实例，所以继承的 start（项目中为 run）调用 self.create_state(goal) 时，会使用子类重写的方法。super() 是内置功能，此处用于复用父类实现，不需要导包。

本次检查覆盖父类字段保留、父类行为不受影响、继承方法调用子类实现及不同任务状态独立。下一步学习 Coding Agent 的代码观察与精确修改工具；本练习完成不代表 demo7 全部完成。
