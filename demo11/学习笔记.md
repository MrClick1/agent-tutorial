# demo11 学习笔记

## 回答问题

- <code>往 WEATHER_DATA 新增城市</code>：可以新增成都，字段保持 weather、temperature、wind 和 suggestion 四项。query_weather 会自动从字典读取，list_supported_cities 也会自动包含新城市。修改后应分别测试“查询成都”和“列出支持城市”，确认 MCP Server 返回结果与 Agent 最终回答一致。

- <code>添加查询穿衣建议工具</code>：可以在 weather_server.py 增加带 @mcp.tool() 的 recommend_clothing(city: str)。函数先校验城市是否支持，再根据天气和温度返回建议。Client 重新启动时，mcp_adapter 会通过 list_tools 自动发现该工具，暴露名会带 weather_ 前缀，因此不需要在 AgentRuntime 中新增分发分支。

- <code>去掉“优先调用天气工具”的系统约束</code>：由于 tool_choice 仍然是 auto，模型可能根据工具 description 继续调用，也可能直接利用自身知识生成答案，调用稳定性会下降，并有伪造实时天气的风险。这个实验说明 schema 决定“能调用什么”，system prompt 影响“什么时候调用”。若业务要求天气问题必须调用工具，应增加确定性路由或强制 tool choice，而不是只依赖提示词。

## 总结

demo11 在 demo6 Runtime 上接入 MCP。weather_server 使用 FastMCP 暴露工具，mcp_agent_demo 通过 McpServerConfig 启动 stdio Server，mcp_adapter 将远程工具 schema 转换为 ToolDefinition，并把调用结果适配为 Runtime 能处理的字典。当前天气数据是本地静态数据；适配器每次调用重新连接，尚缺连接复用、超时、重试和权限审批。
