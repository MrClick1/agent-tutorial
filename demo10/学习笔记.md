# demo10 学习笔记

## 回答问题

- <code>新增知识库文档并观察变化</code>：可以在 knowledge_base 下新增一篇内容明确、与现有文档不同的 Markdown，例如 agent_security.md，并设计一个只有新文档能回答的问题。重新启动 demo 会执行 rebuild_index，生成新 chunk 和 embedding，并重建 pgvector 表。应检查检索结果的 source 是否命中新文档，以及最终回答是否引用其内容。注意重建会调用 Embedding API 并执行 TRUNCATE，存在时间和费用成本。

- <code>调整 chunk、overlap 和 Top-K</code>：不能只凭“回答看起来更好”判断。应准备固定问题和 Ground Truth，记录 Recall@K、MRR、正确答案是否进入上下文、检索延迟和上下文 token。chunk 太大会降低定位精度，太小会破坏语义；overlap 增大能缓解边界切断但增加重复；Top-K 增大提高召回机会，也会引入噪音和成本。

- <code>询问知识库中不存在的问题</code>：当前 prompt 要求资料不足时明确说明，但向量检索总会返回最近的 Top-K，因此模型仍可能利用不相关片段回答。稳健方案是在检索层增加距离阈值或 answerability 判断，没有足够相关资料时不构造伪上下文，并要求回答“当前知识库没有相关资料”。测试应关注拒答是否稳定，而不只是单次结果。

## 总结

demo10 展示完整 RAG 链路：读取 Markdown、按字符切分并保留 overlap、调用 embedding-3、写入 PostgreSQL pgvector、用相同模型编码查询、按余弦距离检索 Top-K，再把资料交给 LLM 回答。当前实现适合教学，生产化还需要增量索引、混合检索、重排、引用校验、离线评测和权限隔离。
