# demo5 学习笔记

## 回答问题

- <code>先生成文件，再读出来检查</code>：用户可以要求“生成 python_learning_plan.md，保存后重新读取并检查 Markdown 格式”。理想链路是 create_text_file → role=tool → read_text_file → role=tool → 最终回答。这个练习验证模型是否会根据真实工具结果继续行动，而不是写入后立即口头声称检查完成。

- <code>列出文件并继续处理</code>：用户可以要求“列出根目录文件，选择一个 Markdown 文件读取并总结”。模型应先调用 list_files，再根据 items 选择路径，然后调用 read_text_file。若目录为空或没有合适文件，应如实说明或询问用户，不能编造文件名。

- <code>增加一个工具</code>：适合增加 file_exists 或 count_text_lines 这类低风险只读工具。需要在 build_tools 中加入 schema，在 tools.py 实现函数，并在 execute_tool_call 增加分发。主循环不应因为工具增加而改变，它只处理统一的 tool_calls 和 role=tool 结果；如果每增加工具都要修改 agent.py，说明工具层与调度层耦合过高。

## 总结

demo5 从固定 Planning 转向 ReAct：模型可以根据 messages、state 和工具观察动态决定下一步。它同时维护协议历史和结构化任务状态，支持创建、读取和列举文件，并通过最大循环次数控制失控风险。相较 demo4，它更灵活，但也更依赖工具设计、提示约束和循环保护。
