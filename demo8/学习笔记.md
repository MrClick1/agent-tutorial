# demo8 学习笔记

## 回答问题

- <code>新增 risk check 节点</code>：可以把 RiskCheckNode 插在 plan 和 apply 之间，检查目标路径、修改范围、expected_occurrences、是否整文件覆盖和是否涉及敏感文件。节点返回 safe 时进入 apply，返回 blocked 时进入 report。原流程刚好包含六个节点，引入新节点后还要把 MAX_WORKFLOW_STEPS 从 6 至少提高到 7，否则流程可能在 report 前达到上限。

- <code>比较自由 Agent 与固定 Workflow</code>：可用同一个“修改 DEFAULT_THEME”任务测试。自由 Agent 通常会动态选择 search、read、replace，工具次数可能变化；Workflow 固定执行 classify、inspect、plan、apply、verify、report，步骤可预测、日志更清楚，但简单任务也要走完整流程。应比较成功率、步骤数、token、延迟、错误定位和安全性。

- <code>让 VerifyNode 多做结果总结</code>：VerifyNode 可以在重新读取文件后，不只保存 snapshot，还检查 new_text 是否存在、old_text 是否消失、实际替换次数是否符合计划，并生成 verification_summary。若校验失败，应把 ok 设为 False 并进入 report，而不是只要文件能读取就认为验证成功。

## 总结

demo8 把自由循环改造成显式 Workflow。每个节点职责单一，通过 action 和 route 决定下一跳，CodeWorkflowContext 保存节点共享状态。典型链路是 classify → inspect → plan → apply → verify → report。Workflow 更适合步骤稳定、需要审计和验证的任务，但当前实现仍缺少 checkpoint、恢复、超时和完整失败状态。
