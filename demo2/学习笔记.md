# demo2 学习笔记

## 回答问题

- <code>调整保留轮数</code>：MAX_TURNS 越大，模型能看到的历史越多，处理“继续讲”“刚才那个例子”等指代更可靠，但 token、延迟和成本都会增加；MAX_TURNS 越小，成本更低，却更容易忘记早期约定。可以先告诉模型一个偏好，经过多轮对话后再次追问，分别在 MAX_TURNS 为 1、4、8 时观察它是否还记得。

- <code>增加更强的人设约束</code>：可以在 system message 中加入“你是一名 Python 面试教练；回答先给结论，再给原因，最后给一个检查题；不要编造运行结果”。稳定的人设规则适合放在 system 中，但它不能代替程序安全边界，也不能保证模型百分之百遵守。

- <code>打印每轮消息数量</code>：在调用 call_llm 前打印 len(messages)，还可以打印每条消息的 role。正常情况下，新的一轮会追加 user 和 assistant 两条消息；超过 max_turns 后，数量会被 trim_messages 限制。更完整的观察还应统计 token，因为消息条数相同不代表文本长度相同。

## 总结

demo2 说明所谓短期记忆，本质上是维护 messages，并在下一次请求时重新发送历史。程序会保存 user 和 assistant 消息，用最近若干轮裁剪控制成本，并在请求失败时回滚刚加入的 user 消息。当前记忆只存在于进程内，不是数据库持久化或跨会话长期记忆。
