# demo6 学习笔记

## 回答问题

- <code>新增一个自己的 @tool</code>：可以在业务工具模块中增加 count_text_lines(relative_path)，使用 @tool 声明描述和参数说明，复用安全路径解析，返回 ok、line_count 和 context_updates。将整个模块传给 create_runtime 的 tool_modules 后，ToolRegistry 会扫描 __tool_definition__ 并自动注册，不需要修改 AgentRuntime。

- <code>增加更严格的循环次数限制</code>：可以在 create_runtime 时显式传入 max_loops=4，或者从 config.py 导入 MAX_AGENT_LOOPS 后传入。达到上限时 Runtime 会抛出异常。更严格的生产保护还应检测连续相同的工具名和参数、限制总 token、总耗时和有副作用工具的调用次数。

- <code>替换 MessageStore 和 ToolRegistry 的影响</code>：MessageStore 只要保留 append、extend、snapshot 等 Runtime 需要的接口，就可以改成数据库存储或 token-aware 裁剪，主要影响 helpers 和消息持久化层。ToolRegistry 只要保留 build_tools_payload 和 execute_tool_call，就可以增加 JSON Schema 校验、权限和远程工具，主要影响工具注册与执行层。清晰接口使 Runtime 不必知道具体实现。

## 总结

demo6 是架构分水岭：它把前面验证过的模型调用、工具注册、消息存储和 ReAct 循环抽成最小框架。@tool 把函数签名转成 ToolDefinition，ToolRegistry 负责模型 schema 和真实 handler，MessageStore 管理历史，AgentRuntime 负责调度。业务工具可以通过 context_updates 向 shared_context 回写结构化状态。

## 工具注册与调用模块复盘

完成日期：2026-10-12。对应练习：Python-Agent练习/lesson_02_tool_call.py、lesson_03_tool_decorator.py、lesson_04_tool_registry.py。装饰器与注册表练习均通过 4/4 项检查。

### 要解决什么问题

模型只能给出工具名称和参数，真正执行 Python 函数需要框架完成。工具注册表把名称、说明、参数定义和实际函数连接起来。

```text
业务函数 → @tool 附加 ToolDefinition → register 保存到 _tools
                                         ↓
                          build_tools_payload 给模型工具说明
                                         ↓
模型返回工具名称和 JSON 参数 → json.loads → 按名称查找定义
                                         ↓
                        handler(**arguments) → 返回工具结果
```

### 三个方法各自负责什么

| 方法 | 职责 | 核心代码 |
| --- | --- | --- |
| register | 读取装饰器附加的定义，按名称保存 | self._tools[definition.name] = definition |
| build_tools_payload | 生成可序列化的工具说明 | 遍历定义，提取 name、description、parameters |
| execute_tool_call | 解析参数、找工具、执行、返回 | return definition.handler(**arguments) |

handler 是本地函数对象，不放进发给模型的 JSON。模型根据说明选择工具，程序负责执行。装饰器附加属性不等于注册；还需要 register 把定义加入注册表。

### 具体调用与本次易错点

```python
arguments = {"a": 3, "b": 5}
# handler 指向 add(a, b)
return definition.handler(**arguments)
# 相当于 return add(a=3, b=5)
```

`**arguments` 把字典展开成关键字参数。省略双星号会把整个字典当作一个位置参数；对 add(a, b) 来说会缺少 b。

工具函数的 return 只把结果交给 execute_tool_call。外层也要 return，才能将结果继续交给 Runtime；仅调用函数而不返回，成功路径会隐式返回 None。本次练习曾因此只通过 3/4 项。

占位的 raise NotImplementedError 必须在实现后删除；它会主动抛出异常，即使上一行已经完成了保存操作。handler 拼写错误会产生 AttributeError，except TypeError 不会捕获它。

### 错误处理的边界

非法 JSON 返回错误字典，未知工具返回错误字典，参数不匹配或工具显式抛出的 TypeError 也返回错误字典。except 只捕获匹配类型及其子类，并不会处理所有异常。返回 ok=False 是项目约定，不会自动触发重试。

当前练习只接受装饰后的函数；项目原版还接受 ToolDefinition，并提供批量注册与模块扫描。检查通过表示这些练习用例正确，完整工程仍需考虑参数结构校验及其他业务异常。

### 面试表达与下一步

工具注册层把业务函数整理为名称到定义的映射，并生成模型可读的工具 schema；执行层解析模型返回的参数，按工具名找到 handler，通过关键字参数展开调用，返回结构化结果。
