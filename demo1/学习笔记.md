# demo1 学习笔记

## 回答问题

- <code>改写 system prompt</code>：可以把助手从“面向初学者的 Python 和 Agent 助手”改成代码审查助手，例如要求它先指出问题，再给出修改建议，并使用简洁中文。system prompt 适合放长期稳定的身份和行为规则，不适合放只对当前一次请求有效的具体任务。修改后应观察相同 user prompt 下，回答的角色、语气和结构是否稳定变化。

- <code>改写 user prompt</code>：可以把原问题改成“请比较普通聊天机器人和 Agent，并各举一个例子”。user prompt 表示当前任务，应该说明目标、必要背景和输出要求。它与 system prompt 的区别是：system 管长期规则，user 管当前需求。

- <code>调整 temperature 和 max_tokens</code>：temperature 较低时输出通常更稳定、重复运行差异更小，适合事实问答和结构化任务；较高时表达更丰富，但随机性更强。max_tokens 决定最大生成长度，过小可能截断答案，过大则增加成本上限。练习时可以固定 prompt，分别尝试 temperature 为 0.2 和 1.0，再比较答案差异；max_tokens 可以从 50、200、500 逐步调整。

- <code>打印完整返回 JSON</code>：完整响应中最值得观察的是 choices、choices[0].message、finish_reason 和 usage。message.content 是正文；finish_reason 可以帮助判断是正常结束还是达到长度上限；usage 记录输入、输出和总 token。打印时使用 json.dumps(result, ensure_ascii=False, indent=2) 更容易阅读，但不要把 Authorization 或 API Key 打印出来。

## 总结

demo1 是整个项目的地基，只完成一次最小 LLM 调用：构造 system 和 user 消息，通过 HTTP 请求调用模型，再从响应中读取文本与 token 使用量。它还不是 Agent，因为没有多轮历史、工具、状态和执行循环。学习重点是理解消息协议、请求参数、HTTP 错误和模型响应结构。
