# demo3 学习笔记

## 回答问题

- <code>生成一个 Markdown 文件</code>：可以输入“请创建 notes/agent-outline.md，内容是一份包含三级标题和列表的 Agent 学习大纲”。模型应返回 create_text_file 的 tool_call，程序解析 relative_path、content 和 overwrite，真实写入 demo3/generated_files，随后把 role=tool 结果反馈给模型。只有工具返回 ok=True 后，助手才能声称文件已创建。

- <code>使用复杂内容观察参数错误</code>：可以要求生成包含多行代码、双引号、反斜杠和 Markdown 代码块的文件。function.arguments 本质上是 JSON 字符串，这些内容都需要正确转义；内容过长时也可能出现参数截断。应重点观察 raw_arguments、json.loads 是否成功、finish_reason 是否异常，以及工具错误能否反馈给模型进行修正。

- <code>新增只读工具</code>：可以增加 read_text_file(relative_path)。需要完成四步：定义工具 schema；实现安全路径解析和 UTF-8 读取；在 execute_tool_call 中增加工具名分支；将结果作为 role=tool 消息写回。只读工具仍要使用同一个目录沙箱，并处理文件不存在、目录误读和内容过长等情况。

## 总结

demo3 第一次形成 Tool Calling 闭环：模型只负责选择工具并生成参数，Python 程序负责校验和执行，再把真实结果反馈给模型。项目用 resolve_safe_path 限制文件写入范围，并用最大工具轮数避免无限循环。核心认识是 LLM 不会直接执行函数，真正的权限和副作用边界必须写在程序里。
